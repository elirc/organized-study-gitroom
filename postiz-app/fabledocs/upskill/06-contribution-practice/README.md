# 06 — Contribution Practice

Turn reading into shipping. Realistic contributions only — every one answers: why useful, why small blast radius, what pattern it follows, how it's tested, what would make a maintainer reject it.

1. [01-good-first-tickets.md](01-good-first-tickets.md) — 18 junior tickets across the stack.
2. [02-mid-level-feature-tickets.md](02-mid-level-feature-tickets.md) — 12 cross-layer tickets; design notes required before code.
3. [03-senior-build-projects.md](03-senior-build-projects.md) — 6 projects (days→weeks) with full design/migration/test/rollout plans.
4. [04-refactor-and-design-katas.md](04-refactor-and-design-katas.md) — senior refactoring exercises with self-grading.

Every ticket carries an "Interview story potential" line — completing it produces a STAR story ([08-interview-prep/06](../08-interview-prep/06-behavioral-star-stories.md)). Remember: no test infra exists, so ticket J17 (bootstrap tests) multiplies the value of everything else — consider it a prerequisite for the "how is it tested" field to mean anything.
